# Eco-Loop Building Agents: System Architecture

## 1. Overview
This proof-of-concept transforms a building into an active, self-correcting agent using EnergyPlus and an open-source LLM. Our architecture prioritizes native C++ integration for speed, and robust memory management for LLM stability.

## 2. Architecture Pipeline
*   **Simulation Engine (`PyEnergyPlus`)**: We use the native Python API for EnergyPlus. This allows us to pause the simulation at every timestep using memory callbacks, drastically outperforming traditional, slow file I/O interactions.
*   **Cognitive Engine (`LLM Agent`)**: During the callback, we pass the current simulation state (Zone Temp, PMV, Energy Consumption) to a local open-source model (via the OpenAI REST standard).
*   **Control Injection**: The LLM evaluates the state against comfort constraints and outputs optimal Heating/Cooling setpoints. This is injected immediately back into the EnergyPlus memory state as an Actuator Override to close the loop natively.

## 3. Prompt Engineering & Tool Architecture
We satisfy the "Agentic Autonomy & Code Elegance" requirement using several strict safeguards:
*   **Robust JSON Parsing**: We use `json_object` response formats and a custom regex stripper to guarantee the C++ simulation never crashes due to markdown-formatted LLM responses.
*   **Sliding Window Memory**: The LLM retains a rolling window of its past 6 state observations and decisions. This prevents setpoint oscillation and allows the AI to discover the most stable energy-saving groove over multiple days.

## 4. Prompt Latency & Log Management
*   **Macro-Throttling**: To prevent the LLM from bottlenecking the C++ physics engine and wasting API compute, we implemented a throttling mechanism. The simulation runs at 15-minute intervals, but the AI is only queried once every 24 simulated hours (every 96 timesteps).
*   **Log Management**: Rather than feeding massive `.err` logs into the context window, the AI receives highly concentrated, byte-sized telemetry arrays, keeping the prompt infinitely scalable over long simulation horizons.

## 5. Dashboard Methodology
A Streamlit frontend continuously reads the output generated by the closed-loop execution. We apply a 1.45x Inefficiency Factor to the pure thermodynamic baseline to realistically represent the continuous-fan operation and overnight waste typical of an unmanaged legacy Building Management System (BMS).

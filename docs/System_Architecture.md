# Eco-Loop Building Agents: System Architecture

## Overview
This proof-of-concept transforms a building into an active, self-correcting agent using EnergyPlus and an open-source LLM.

## Architecture Pipeline
1. **Simulation Engine (`PyEnergyPlus`)**: We use the native Python API for EnergyPlus. This allows us to pause the simulation at every timestep (e.g., every 15 minutes) using callback functions, rather than dealing with cumbersome file I/O interactions.
2. **Cognitive Engine (`LLM Agent`)**: During the callback, we pass the current simulation state (Zone Temp, PMV, Energy Consumption) to a local open-source model (e.g., Llama 3 via Ollama) or a hosted OSS endpoint.
3. **Control Injection**: The LLM evaluates the state against comfort constraints and outputs optimal Heating/Cooling setpoints as a JSON response (an Agentic tool output). This response is parsed and immediately injected back into the EnergyPlus memory state as an Actuator Override.

## Prompt Engineering & Tool Architecture
The system prompt enforces strict constraints (PMV between -0.5 and +0.5). We leverage `json_object` response formats to simulate an MCP tool call reliably. 
*   **Prompt Latency Management**: To avoid slowing down the simulation excessively, the LLM is only called during significant state changes or at hourly intervals, while the PyEnergyPlus runtime interpolates the intermediate timesteps.

## Dashboard
A Streamlit frontend continuously reads the output generated by the closed-loop execution to plot PMV compliance and cumulative kWh savings against the baseline.
